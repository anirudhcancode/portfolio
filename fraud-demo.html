Fraud Detection Pipeline

This system looks at a credit card transaction and decides in milliseconds whether it is likely to be fraudulent or legitimate — the same way your bank automatically flags suspicious purchases on your card.

In Plain Terms

Every credit card transaction leaves a trail — amount, time, location, spending pattern. This system studies 284,807 real transactions to learn what fraud typically looks like, then flags new transactions that match those patterns before they're approved.

Under the Hood

A PySpark pipeline engineers behavioral features — rolling transaction counts, spending averages, time-based patterns — using Spark's distributed windowing. Random Forest and XGBoost classifiers were trained and compared; Random Forest was deployed via FastAPI (containerized with Docker) for its stronger recall, prioritizing catching fraud over minimizing false positives.

How it works

What does this system actually do?

1

Learns from 284,807 real transactions

The system was trained on a real dataset of credit card transactions — each one labeled as either legitimate or fraudulent. It learned the patterns that separate normal purchases from suspicious ones.

2

Analyzes behavioral signals

It doesn't just look at the transaction amount. It considers behavioral patterns — how many transactions happened recently, what time of day it is, whether the amount is unusually large compared to recent history.

3

Returns a fraud probability score

For every new transaction, the system returns a label (Legit or Fraud) and a probability score. A score of 4% means very likely legitimate. A score of 95% means very likely fraud.

About the Input Format

The API accepts 33 numerical features. The first 28 (V1-V28) are PCA-transformed and anonymized by the original data provider for privacy reasons — they represent patterns in the raw transaction data but are not human-readable. This means you cannot construct a meaningful custom transaction from scratch. The preset examples above use real transactions directly from the dataset. In a production bank system, these features would be interpretable — merchant category, geographic location, device fingerprint, and spending history.

A score of 0.98 out of 1.0 means that if you showed the model a real fraud case and a legitimate transaction side by side, it would correctly identify the fraudulent one 98% of the time. It catches 83% of all fraud cases in the test set.

Model Selection

Random Forest was selected for deployment (83% recall, 77% precision) over XGBoost (84% recall, 89% precision) to prioritize catching fraud over minimizing false positives — a deliberate tradeoff given the cost asymmetry of missed fraud vs. flagged legitimate transactions.
